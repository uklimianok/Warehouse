# Warehouse Enterprise Application
A REST backend for a warehouse that processes orders from stores. It covers the full
flow of goods: receiving product pallets, storing them at work stations, picking orders
onto pallets, and exporting, loading and shipping them. Employees work with positions
that define what they can see and change.

## Tech stack
- **Backend:** Java 21, Spring Boot 4.1 (Web MVC, Data JPA, Security, Validation, WebSocket), MapStruct, Lombok
- **Data:** PostgreSQL 18, Flyway, Redis 8
- **Messaging:** Apache Kafka 4.2
- **Security:** Keycloak 26 (OAuth2 / JWT resource server)
- **Testing:** JUnit 5, Testcontainers, Awaitility
- **Runtime:** Docker Compose

## Architecture highlights
- **Access control from the database:** each position has CRUD flags per controller; the JWT is used
  only to identify the employee, so a position change takes effect immediately
- **Response shapes per position:** the same endpoint returns a Full, Transfer or default view
- **Status workflows:** product pallets, order pallets and orders follow strict step-by-step chains;
  order status changes automatically from its pallets
- **Action log:** an AOP aspect publishes every create/update/delete to Kafka; a consumer stores it
- **Live notifications:** unloaded product pallets are announced to clients through Kafka and WebSocket
- **Caching:** Redis caches only entities without relations (Workshop, Gate, Pallet, Status, Shift,
  Department, OrganizationType)

## Running locally
Requirements: Docker with Docker Compose.

1. Copy `.env.example` to `.env` and fill in your values.
2. Start everything:
```bash
docker compose up -d     # -d: run in the background
```
3. Keycloak imports the `warehouse` realm from `keycloak/` on first start.

| Service | URL / port |
|---|---|
| API | http://localhost:8280 |
| Keycloak | http://localhost:8286 |
| PostgreSQL (app) | localhost:8281 |
| Redis | localhost:8282 |
| Kafka | localhost:8283 |

Get a token from `http://localhost:8286/realms/warehouse/protocol/openid-connect/token`
and call the API with `Authorization: Bearer <token>`; `GET /whoami` is a quick check.
### Getting a token (Postman)
Use OAuth 2.0 with these settings:

| Setting | Value |
|---|---|
| Grant type | Authorization Code (With PKCE) |
| Authorize using browser | enabled |
| Auth URL | http://localhost:8286/realms/warehouse/protocol/openid-connect/auth |
| Access Token URL | http://localhost:8286/realms/warehouse/protocol/openid-connect/token |
| Client ID | `postman` |
| Scope | `openid` |
| Auth request | `prompt` = `login` |

Click **Get New Access Token** and log in with an employee number. Demo users:
`03000001` (Goods Picker, no password), `09000001` (Data Controller) and
`24000001` (System Administrator). For the last two, first set a password in the
Keycloak admin console (http://localhost:8286, user `keycloak`, password
`KC_BOOTSTRAP_ADMIN_PASSWORD`): Users → select the user → Credentials.

## Tests
The integration tests start real PostgreSQL, Redis, Kafka and Keycloak containers
with Testcontainers, so **Docker must be running**. No `.env` is needed for tests.

```bash
./mvnw clean verify                      # all 127 tests
./mvnw verify -Dit.test=OrderFlowIT      # one test class
```

Test classes end with `IT` and are run by the Maven Failsafe plugin.

| Layer | Classes | What it proves |
|---|---|---|
| Infrastructure | `SmokeIT`, `WhoAmIIT` | containers, tokens and authentication work |
| Access control | `AccessIT` | read and create rights per position, taken from the database flags |
| Error paths | `ErrorIT` | 400 / 401 / 404 / 409 responses |
| Business flows | `*FlowIT` | full workflows: employees, positions, product pallets, orders, action log |

## Business rules worth knowing
- **Departments have priorities** (a lower number means a higher rank): an employee may edit
  employees whose department priority is the same as theirs or higher, and assign only positions
  in that range. Example: priority 20 can manage priority 20 and 30, but not 10.
  Editing employees also requires the `U` flag on `EmployeeController`.
- **Self-service role switch:** warehouse employees may change only their own position, and only to
  positions whose department priority is 30 or higher
- **Access flags are not inherited;** position inheritance affects business rules only
- **The 25 seeded positions can't be deleted;** they are the base for custom positions
- **Strict status chains:** product pallets, order pallets and orders move one step at a time,
  with no jumps, even for supervisors
- **Reopening orders:** adding a pallet to a Sent order moves it back to Processing
- **Action logs are read-only:** only the server creates them (from Kafka events)
- **Generated identifiers:** `employeeNumber` and `palletNumber` are unique business numbers,
  generated by the server and immutable; the database `id` is still used in URLs
- **Sent orders can still be edited** (store, gate, note) by users with update rights, as long as the status stays the same except the orders proceeder, who can edit only Accepted orders

## Database migrations
Schema and seed data are managed by Flyway in `src/main/resources/db/migration`
(`V1__…` to `V41__…`). They run automatically when the app starts.

- **Never edit a migration that has already been applied.** Flyway stores a checksum
  of every applied file; if a file changes, validation fails and the app won't start.
- **To change something, add a new migration** with the next number, for example
  `V42__rename_something.sql`.

## Roadmap (v3)
- **Cache DTOs instead of entities**, so related entities can be cached too
- **More WebSocket notifications**, for example:
    1. Set goods loaders: all pallets for their truck are ready to load
    2. Data controllers: call a warehouse employee to the office
    3. Operators: replace an empty product pallet with a full one
- **Productivity tracker:** work done per hour for each warehouse employee,
  paused while the employee reports a problem
- **Publish Kafka events after the database commit** (transactional outbox)
- **Full write-access matrix** in the tests (create, update and delete for every position)
